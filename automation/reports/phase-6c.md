# Phase 6C — release and deployment checks

Added `npm run check:release`, an offline release gate that runs the complete test suite, syntax checks, Prisma schema validation, frozen acceptance evaluation and comparison against recorded independent HA semantic captures. It strips database/provider configuration from child processes so ordinary verification does not touch configured accounts. Added `npm run check:automation-config` (and `-- --production`) to report configuration requirements without printing secret values. It deliberately does not claim to validate credentials or database connectivity.

Fixed HTTPS termination behavior: Origin now compares against the configured public origin, not the internal HTTP request protocol. Foreign Host/Origin requests still reject, and forwarded headers are not trusted. PUBLIC_URL now rejects embedded credentials and non-origin components. Production-mode tests cover these checks, absent-token rejection, closed registration and the disabled demo login route.

Actual browser verification found a browser-only fetch receiver problem that the Node-injected client test did not expose. The default fetch adapter now invokes the browser function without an arbitrary receiver; a focused regression test covers it. The final browser session successfully registered a disposable memory account, imported the example through MCP, ran preflight, replayed before/after and showed the guard retaining the lamp at 600 ms. The screenshot is stored locally under ignored `artifacts/automation/phase-6-mcp-workshop.jpg`.

`automation/deployment.md` provides clean-checkout, Neon/Gemini, optional single-instance HTTPS, reviewer account, verification and recovery instructions. Hosting remains optional for the permitted local simulation route. Native Alexa tools are unavailable to ordinary hackathon participants according to the current official FAQ; production account linking is not represented as implemented. No domain, hosting bill, collaborator invitation or external submission was created.

Verification before this step: full suite 129 passed / 2 opt-in database tests skipped; 107 JavaScript files parsed; Prisma schema valid; 13/13 acceptance cases; all six recorded HA semantic comparisons agreed. The subsequent browser receiver regression adds one passing test. The final report records the final clean-checkout release result.
