# October 21 release — focused workshop and final engineering checks

## Product changes

The workshop now has three primary views: Investigation, Replay and Repair. Source context and independent runtime evidence remain accessible under Project details. An open project no longer carries the large onboarding headline, repeated slogan or decorative diagram. Import occupies its own focused view; closing it restores the current project. The first confirmed finding is prominent, while further findings, assertion details, timing counterexamples and coverage remain expandable. Counts use a quiet inline strip instead of competing cards. Repair limitations remain available on demand, and the exact patch and explicit approval remain visible at the export step.

The cream, forest-green and restrained amber theme is consistent across the views. Mobile workspaces collapse into a switcher instead of occupying the top of every screen. Touch controls, visible focus styles, editable transcripts, no automatic voice submission, and reduced-motion behavior are retained. Conversation history, before/after replay, imported source and runtime evidence are still part of the same real MCP workflow.

## Dependencies and storage reliability

Prisma/client were updated together from 6.19.1 to **6.19.3**. That patch updates Effect; `@prisma/config` additionally has a narrowly scoped override to **deepmerge-ts 8.0.2** at both package roots. Its named deepmerge entry point is retained; the override applies only to Prisma configuration, not automation execution. Prisma generation, schema validation, the full regression gate and the separately enabled Neon persistence/concurrency test verify the resulting setup. No database schema or user data migration was needed for this patch.

Both installed-package audits report **zero vulnerabilities**. The four Prisma-chain entries recorded in the October 16 report are resolved by this release; that earlier risk statement is historical. This is an audit result at release time, not a guarantee about future advisories. Relevant dependency source: [Prisma 6.19.3 configuration package](https://www.npmjs.com/package/@prisma/config/v/6.19.3), [deepmerge-ts release notes](https://github.com/RebeccaStevens/deepmerge-ts/releases).

A live Neon test initially exceeded its connection timeout. DNS/TCP diagnostics succeeded and a 20-second connection setting passed. Runtime connection setup now adds `connect_timeout=20` only to Neon PostgreSQL URLs without an explicit timeout. Existing operator timeout values, TLS/schema/credential parameters and all non-Neon connections are preserved. It performs no automatic replay of a failed database write. The same options are used in the opt-in Neon test; it passed without modifying the private env file and cleaned up its own synthetic records. CLI migration commands continue to use the operator URL unchanged.

## Verification and merge gate

The final local release gate passed **134 tests total: 132 passed, zero failed, two external database tests skipped**. Syntax checks parsed 108 JavaScript files; Prisma schema validation, all 13 frozen acceptance cases and all six recorded HA semantic comparisons passed. The separately enabled Neon test also passed using the new runtime connection options. Browser QA covers registration, focused import, direct preflight, disclosure navigation, exact patch review, clearing approval when editing and responsive layout. The local viewport measurement showed no horizontal document overflow at the tested mobile size; the override was reset after checking. CI status is recorded in the PR and handoff.

The GitHub Actions workflow runs the same offline release gate, client generation and both dependency audits on pushes to `main` and `new/automation` and on main-targeting PRs. Actions are pinned to verified commit hashes and run with read-only repository contents permission; no database/provider secret is supplied to CI. Live provider and Neon tests remain separately enabled.

This release is pushed to `new/automation` and integrated into `main` through a normal GitHub PR after checks. The development branch is retained. No force-push, history reset, repository visibility change or license choice is part of the release.
